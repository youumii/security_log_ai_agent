# Security Log AI Agent — Portfolio Edition

## 프로젝트 소개

**AI 기반 보안 로그 이상행위 탐지 및 자동 보고 시스템**

인증 로그를 입력하면 Python 기반 탐지 엔진이 사용자와 IP의 로그인 패턴을 분석하고,
위험도를 계산한 뒤 사람이 읽기 쉬운 보안 분석 요약과 TXT/JSON 보고서를 생성합니다.

단순히 로그인 실패 횟수를 누적하는 방식이 아니라 **시간 구간(window)** 을 사용하여
짧은 시간 안에 반복되는 인증 실패를 탐지합니다.

---

## 핵심 기능

### 1. 로그 파싱

지원 형식:

- CSV: `time,user,event,ip`
- Linux SSH `Failed password`
- Linux SSH `Accepted ... for ... from ...`

깨진 로그는 분석에서 제외하고 별도 목록으로 표시합니다.

### 2. 시간 기반 Brute Force 탐지

기본 규칙:

```text
60초 안에 동일 사용자 로그인 실패 5회 이상
```

### 3. 동일 IP 다중 계정 공격 탐지

```text
5분 안에 동일 IP가 3개 이상 계정에 로그인 실패
```

Credential stuffing / password spraying 의심 패턴을 단순화한 규칙입니다.

### 4. 실패 후 로그인 성공 탐지

```text
10분 안에 로그인 실패 3회 이상
→ 이후 로그인 성공
```

정상 사용자 실수일 수도 있으므로 공격으로 단정하지 않고 **확인 필요 이벤트**로 표시합니다.

### 5. 동일 계정 다중 IP 실패 탐지

동일 계정에 여러 IP에서 인증 실패가 집중될 경우 별도 탐지합니다.

### 6. 공격 강도 + 영향도 기반 종합 위험도

초기 버전은 위험 요소에 고정 가중치를 단순 합산하여 여러 탐지 항목이 동시에 발생하면 점수가 빠르게 포화되는 문제가 있었습니다.

이를 개선하여 종합 위험도를 두 축으로 분리했습니다.

#### 공격 강도 (0~50)

공격이 얼마나 빠르고 넓게 진행되는지를 평가합니다.

| 항목 | 계산 |
|---|---|
| 로그인 실패 밀도 | 60초 내 5회부터 12점, 이후 실패 1회당 +2, 최대 30 |
| 공격 범위 | 동일 IP의 3개 계정 공격부터 8점, 이후 계정 1개당 +2, 최대 20 |

#### 영향도 (0~50)

실제 침해 가능성을 높이는 후속 징후를 평가합니다.

| 항목 | 점수 |
|---|---:|
| 반복 실패 후 로그인 성공 | +20 |
| 실패 IP와 다른 IP에서 성공 | +15 |
| 동일 계정에 여러 IP에서 실패 | +10 |
| 실패 후 성공 패턴 2건 이상 | +5 |

```text
종합 위험도 = 공격 강도 + 영향도
```

등급:

```text
LOW      0 ~ 19
MEDIUM  20 ~ 49
HIGH    50 ~ 100
```

전체 로그 수로 점수를 나누지는 않습니다. 긴 로그 안에서도 짧은 시간에 집중된 공격이나 침해 가능성이 높은 패턴은 중요하게 평가되어야 하기 때문입니다.

대시보드의 `점수 산정 근거 보기`에서 공격 강도와 영향도를 각각 확인할 수 있습니다.

### 7. 시간대별 그래프

브라우저에서 로그인 실패량을 상대 막대그래프로 시각화합니다.

외부 JavaScript 차트 라이브러리를 사용하지 않아 인터넷 연결 없이도 표시됩니다.

### 8. AI 보조 분석

기본 상태에서는 API 키 없이 **LOCAL_RULE_SUMMARY** 모드가 동작합니다.

환경변수를 설정하면 OpenAI-compatible Chat Completions API에 탐지 결과를 전달하고
자연어 분석을 생성합니다.

```text
LLM_API_URL
LLM_API_KEY
LLM_MODEL
```

### 9. Webhook 알림

`WEBHOOK_URL`이 설정된 경우 전체 위험도가 HIGH일 때만 요약 알림을 보냅니다.

원문 전체나 인증 토큰을 Webhook으로 전송하지 않습니다.

### 10. 자동 보고서

분석 결과를 다음 형식으로 다운로드할 수 있습니다.

- TXT
- JSON

# 실행 방법

## 가장 쉬운 방법 — Windows

압축을 푼 뒤:

```text
run.bat
```

더블클릭.

처음 실행 시 자동으로:

1. venv 생성
2. 라이브러리 설치
3. Flask 실행

을 진행합니다.

브라우저에서:

```text
http://127.0.0.1:5000
```

접속합니다.

## 직접 실행

```bat
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

## 개별 탐지 이벤트와 종합 위험도의 역할

개별 탐지 이벤트에는 별도의 점수나 HIGH/MEDIUM/LOW 등급을 부여하지 않습니다.

```text
개별 탐지 이벤트
→ 무엇이 발견되었는가?
→ 사용자 / IP / 횟수 / 시간 / 탐지 근거

종합 위험도
→ 발견된 위험 요소들을 가중치로 합산하면 전체적으로 얼마나 위험한가?
→ 0~100점, LOW / MEDIUM / HIGH
```

초기 버전에서는 개별 이벤트와 전체 위험도에 각각 별도 점수 체계를 두었지만,
같은 로그에서 서로 다른 위험 등급이 표시될 수 있다는 문제를 발견했습니다.
이를 해결하기 위해 **점수 체계를 종합 위험도 하나로 통합**했습니다.


# 설계 의도

LLM에게 원본 로그 전체를 넘기고 공격 여부를 판단하게 하지 않았습니다.

```text
로그
 ↓
Python 파싱
 ↓
규칙 기반 탐지
 ↓
위험도 계산
 ↓
구조화된 탐지 결과
 ↓
LLM 요약
 ↓
보고서 / 알림
```

보안 이벤트 탐지는 설명 가능하고 재현 가능한 Python 규칙이 담당하고,
LLM은 사람이 읽기 쉬운 설명을 만드는 보조 역할을 담당합니다.

# 한계점

현재 버전은 규칙 기반 탐지이므로 다음 한계가 있습니다.

- 사용자의 실제 정상 행동 패턴을 학습하지 않음
- IP 평판 정보 미사용
- GeoIP 미사용
- 대규모 로그 스트리밍 환경 미지원
- 규칙 임계값이 고정값
- 탐지 이벤트가 실제 공격임을 보장하지 않음

# 향후 개선

- IP Reputation API 연동
- 국가/지역 기반 이상 로그인 탐지
- 사용자별 Baseline 생성
- SQLite/PostgreSQL 로그 저장
- 실시간 로그 수집
- 관리자 로그인 기능
- 탐지 규칙 설정 UI
- SIEM 형태의 대시보드 확장

## 점수 데이터 사용 원칙

- 개별 탐지 이벤트에는 `score` / `risk` 필드를 저장하지 않습니다.
- 최종 점수는 `overall_risk.score` 한 곳에서만 관리합니다.
- AI 요약도 개별 이벤트 점수가 아닌 종합 위험도를 기준으로 설명합니다.


## GitHub 업로드 시 주의

실제 API Key나 Webhook URL이 들어 있는 `.env` 파일은 저장소에 커밋하지 않습니다.
환경변수 형식은 `.env.example`만 공개합니다.
